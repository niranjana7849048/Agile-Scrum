# Sprint Retrospective – Digital Wallet Application

## 1. Retrospective Overview

| Detail | Value |
|---|---|
| Project | Digital Wallet Application |
| Sprint Duration | 10 Working Days |
| Team Size | 5 Developers |
| Meeting | Sprint Retrospective |

## 2. What Went Well?

- Team members collaborated effectively.
- Login and wallet dashboard development progressed smoothly.
- Daily Scrum meetings helped identify blockers.
- Team members communicated technical dependencies.
- The sprint board helped track task progress.

## 3. What Needs Improvement?

- Payment gateway credentials were not available on time.
- API response formats were not finalised early.
- Integration work was delayed by external dependencies.
- The refund-to-wallet request required additional scope discussions.

## 4. Action Items

| Action Item | Description | Owner | Expected Outcome |
|---|---|---|---|
| ACT01 | Confirm API contracts before sprint development begins. | Backend Lead | Reduce frontend-backend integration delays. |
| ACT02 | Verify external service credentials and dependencies before sprint planning. | Scrum Master | Reduce delays caused by unavailable resources. |

## 5. Definition of Done (DoD)

A user story is considered Done only when it satisfies the team's agreed Definition of Done.

| DoD Activity | Completion Criteria |
|---|---|
| Build | Application builds successfully without errors. |
| Testing | Unit and relevant integration tests pass. |
| Code Review | Code is reviewed and approved by another developer. |
| Merge | Approved code is merged into the main development branch. |
| Documentation | Relevant technical documentation is updated. |

## 6. Retrospective Conclusion

The team should continue effective collaboration and daily communication while improving dependency checks and API planning.

The action items will be reviewed during the next sprint to determine whether the improvements have been implemented.
