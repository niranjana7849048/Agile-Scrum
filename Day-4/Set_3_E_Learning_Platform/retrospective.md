# Sprint Retrospective – E-Learning Platform

## 1. Retrospective Overview

| Detail | Value |
|---|---|
| Project | E-Learning Platform |
| Sprint Duration | 10 Working Days |
| Meeting | Sprint Retrospective |
| Technique | Start – Stop – Continue |

## 2. Start – Stop – Continue

### Start

Activities the team should begin doing:

- Confirm external API contracts before starting integration work.
- Discuss dependencies during sprint planning.
- Review sprint progress regularly.

### Stop

Activities the team should avoid:

- Starting integration without confirmed API specifications.
- Accepting new work without assessing its impact.
- Delaying communication about blockers.

### Continue

Activities the team should maintain:

- Conducting regular Daily Scrum meetings.
- Collaborating across development and testing.
- Maintaining transparency through the sprint board.

## 3. SMART Action Items

SMART means Specific, Measurable, Achievable, Relevant, and Time-bound.

| ID | Action Item | Owner | Success Measure | Deadline |
|---|---|---|---|---|
| ACT01 | Confirm API contracts before beginning integration stories. | Backend Lead | All required API contracts are reviewed and approved before development starts. | Before next sprint begins |
| ACT02 | Review external dependencies during sprint planning. | Scrum Master | Every identified dependency has an owner and follow-up plan. | Next sprint planning |
| ACT03 | Monitor sprint progress and unresolved blockers daily. | Development Team | All blockers are recorded and reviewed during Daily Scrum. | Throughout next sprint |

## 4. Expected Improvements

- Fewer delays caused by missing API specifications.
- Better identification of external dependencies.
- Improved communication between teams.
- More reliable sprint planning.
- Better visibility into work progress.

## 5. Retrospective Conclusion

The team identified improvements in dependency management, communication, and sprint planning.

The three SMART action items will be reviewed during the next sprint to check whether the improvements have been implemented.
